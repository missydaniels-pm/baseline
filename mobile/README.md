# Baseline Sync (iPhone)

Shown on the Home Screen as **Baseline Sync**, with a sync badge on the Baseline icon, so testers who also
have the web app on their Home Screen can tell the two apart (owner decision 11/21/26). Rename it to
"Baseline" when it becomes the full app (`CFBundleDisplayName` in `app.json`; the bundle ID doesn't change).
Icon: `generate_icons.py` (`draw_sync_icon`).

Apple Health plan **step 4**: a minimal iPhone app whose only job is syncing Apple Health readings —
heart rate variability (SDNN) and blood glucose — to Baseline's `/api/v1` API. Invite-only (TestFlight
internal testing + the per-account "Health sync enabled" flag an admin sets at `/admin/users`). No sign-up:
people register on the web and sign in here. No other features until the React web frontend ships.

**Stack (owner decisions 11/21/26, BACKLOG Decision Log):** Expo SDK 58 with a *development build*
(HealthKit does not run in Expo Go), `@kingstinct/react-native-healthkit`, `expo-secure-store` for the
sign-in token. Bundle ID `com.mybaselineapp.health`. The native `ios/` folder is generated by
`expo prebuild` / `expo run:ios` and not committed.

## What it does

1. **Sign in** — `POST /api/v1/auth/token` with email, password, the phone's name and its IANA time zone
   (so a phone-first account gets the right days). The token lives in the iOS Keychain.
2. **Gates** — privacy policy out of date → "review it on the web"; Health sync flag off → "isn't on yet",
   nothing syncs.
3. **Consent** — shows the text served by `GET /api/v1/health/consent` and records it
   (`POST`, with the version shown) **before** Apple's Health permission sheet. Read-only: the app never
   writes to Health.
4. **Sync** — for each kind, an *anchored* HealthKit query returns readings added **and deleted** since
   the last sync, in pages of 500; each page is uploaded (≤500 readings + ≤500 deletions per request) and
   only then is the anchor saved, so an interrupted sync resends a page — harmless, the server stores each
   reading once. The first sync reaches back one year. 429 → wait (Retry-After, else 1 min doubling),
   409 → quick retry, network/5xx → backoff; 401/403/400 stop the run. Syncs when the status screen
   opens, when the app returns to the foreground, and on "Sync now".
5. **Withdraw consent** (`DELETE /api/v1/health/consent` — the server deletes every stored reading) and
   **sign out** (`DELETE /api/v1/auth/token`).

Background sync (HealthKit background delivery) is **step 5** — it can only be checked on a real iPhone.

## Files

| File | What |
|---|---|
| `App.tsx` | All screens and the sign-in / consent / sync flow |
| `src/api.ts` | The `/api/v1` client (`{ok, code, error}` responses → `ApiError`) |
| `src/syncCore.ts` | The sync loop, retry policy and paging — no React Native imports |
| `src/syncCore.test.ts` | Its tests (fake HealthKit + fake server), plain Node |
| `src/health.ts` | HealthKit: permission, anchored queries, units (ms, mg/dL) |
| `src/storage.ts` | Keychain: token + one anchor per kind |
| `app.json` | Name, bundle ID, HealthKit entitlement + usage text, ATS (no plain HTTP except local) |

## Run it in the iOS Simulator

Needs **Xcode** (Mac App Store) and its iOS Simulator (`xcodebuild -downloadPlatform iOS`, or Xcode ›
Settings › Components), then `sudo xcode-select -s /Applications/Xcode.app/Contents/Developer`. Node 24.
No Apple Developer account is needed for the Simulator.

**CocoaPods** (the build fetches the HealthKit library's native code with it). On this Intel Mac Homebrew
has no ready-made build and compiles LLVM from source for hours, so it's installed as a Ruby gem with
Homebrew's bundled Ruby instead (11/21/26) — and that Ruby must come first on `PATH` when building:

```bash
RUBY_BIN=/usr/local/Homebrew/Library/Homebrew/vendor/portable-ruby/current/bin
$RUBY_BIN/gem install cocoapods --user-install --no-document     # once; again after a big Homebrew update
export PATH="$RUBY_BIN:$HOME/.local/share/gem/ruby/4.0.0/bin:$PATH" LANG=en_US.UTF-8
```

```bash
cd mobile
npm install
EXPO_PUBLIC_API_URL=http://localhost:5001 npx expo run:ios   # against ./run.sh on this Mac
```

`EXPO_PUBLIC_API_URL` is baked in at build time; leave it unset for production
(`https://mybaselineapp.com`), or use the staging URL. The account you sign in with needs the Health sync
flag on (`/admin/users` on that server).

**Health data in the Simulator:** open the Health app → Browse → Heart → Heart Rate Variability (or
Other Data → Blood Glucose) → Add Data. Then come back to Baseline and tap Sync now. *Known issue
(11/21/26): on this Intel Mac the iOS 26.5 Simulator's Health app opens to a black screen, so no readings
could be added there — reading real Health data is first checked on a real iPhone (step 5).*

**If the app opens on Expo's launcher instead of Baseline:** start the dev server
(`EXPO_PUBLIC_API_URL=… npx expo start --dev-client`) and choose it, or "Enter URL manually" →
`http://localhost:8081`. `expo run:ios` may end with an `osascript` error about the Simulator window on this
Mac — the app is installed anyway.

## Tests

```bash
npm test          # sync loop: paging, deletions, 429/409 backoff, stop on 401/403
npm run typecheck
```

CI runs both (`.github/workflows/test.yml`, job `mobile`). The server side of the contract is covered
by `test_api_auth.py`, `test_health_samples.py` and `test_health_consent.py` at the repo root.
